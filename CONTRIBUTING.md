# Contributing to Cleaning Kompleks

## Workflow

1. Create a focused branch from `main`.
2. Keep changes small and production-oriented.
3. Run the repository checks locally before opening a pull request.
4. Open a pull request with a clear description of the problem and the change.
5. Merge only after required checks pass.

## Commit messages

Prefer imperative, scoped messages such as:

- `feat: add booking form`
- `fix: validate phone input`
- `docs: update setup instructions`
- `ci: tighten repository checks`

## Security

Never commit API keys, access tokens, passwords, or other secrets. Runtime secrets must be provided through the deployment environment.
